## 1. 项目背景与目标
MovieHubPro 旨在构建一个高性能、沉浸式的现代移动端电影资讯平台。项目不仅完成基础 CRUD 业务开发，更深入落地海量电影数据场景下的实时多维度筛选、离线优先分层缓存架构、极简现代化交互界面等进阶能力。
项目核心解决普通影视类 App 普遍存在的两大用户痛点：电影资讯信息过载、多条件组合筛选操作低效，为用户提供流畅、低延迟、无网络可用的电影浏览、搜索、收藏一体化体验。

## 2. 深度架构分析
项目完全遵循 Android 官方 MAD（Modern Android Development）现代安卓开发标准，采用 **MVVM + Repository** 分层架构，分层职责清晰、单向数据流隔离，适配 Jetpack Compose 声明式 UI。

### 2.1 单向数据流（UDF）闭环
App 全局强制单向数据流，数据流转链路闭环无逆向耦合：
1. **数据产生源**：Retrofit 拉取远程电影 JSON 接口数据，Room 本地数据库读取缓存/收藏持久化数据；
2. **数据调度中枢**：`MovieRepo` 作为应用唯一可信数据源，统一完成远程/本地数据合并、ID 去重（`distinctBy`）、DTO 网络实体转领域模型 Domain Model；
3. **状态持有层**：ViewModel 使用 `MutableStateFlow` 处理业务逻辑，将原始领域数据封装为统一 `UiState` 界面状态；
4. **UI 消费层**：Jetpack Compose 通过 `collectAsStateWithLifecycle` 生命周期安全订阅 UI 状态，实现纯状态驱动页面渲染。

### 2.2 响应式编程体系
Room DAO 层全部查询接口返回 `Flow<List<T>>` 响应式数据流，数据库数据变更自动下发至所有订阅页面：
典型场景：电影详情页点击收藏按钮更新本地数据库，收藏列表页面无需手动调用刷新接口，自动感知数据库变化并平滑更新列表，无页面重载、无卡顿闪烁。

## 3. 功能模块详解
### 3.1 首页：多维度复合动态布局
首页采用单一 `LazyColumn` 作为顶层容器，无缝嵌套多种横向、纵向滚动组件，分区展示不同电影内容：
- **Hero 轮播横幅**：基于 `HorizontalPager` 实现全屏电影背景轮播，搭配垂直线性渐变遮罩，解决深色/浅色海报背景下标题文字可读性差的视觉问题；
- **快捷分类标签栏**：内置 8 组高频电影分类标签，点击直接携带分类参数跳转筛选页面，实现首页快速导流；
- **横向趋势影片流**：主列表嵌套 `LazyRow` 横向卡片列表，通过卡片 `elevation` 阴影属性构建多层视觉悬浮层级。

### 3.2 多维复合筛选系统（核心技术亮点）
区别于仅本地内存过滤的简易搜索，本项目实现**服务端驱动多条件交叉筛选**，所有筛选逻辑交由后端 API 分页处理，适配海量电影数据：
1. **参数映射转换**：ViewModel 内置映射规则，将前端中文筛选标签（如「2020年代」「日韩地区」）自动转换为 TMDB API 标准请求参数 `with_original_language`、`primary_release_year`；
2. **动态交叉过滤算法**：支持「影片类型 + 地区 + 上映年份」多维度同时筛选；若某维度选择「全部」，构造请求 URL 时自动剔除该参数，动态调整接口查询范围。

### 3.3 收藏批量管理模块
对标商业影视 App 设计批量管理模式，优化多收藏项操作体验：
- 触发方式：长按收藏条目 / 顶部「编辑」按钮进入多选状态；
- 选中状态管理：ViewModel 使用 `Set<Int>` 存储选中电影 ID，高效增删选中标识；
- 批量删除能力：底层通过 SQL `IN` 查询 + 协程并发执行批量删除，避免单条循环删除带来的性能损耗。

## 4. 数据持久化分层设计
### 4.1 Room 本地数据库双表架构
采用双表隔离业务数据，完整支撑离线访问能力：
1. `favorite_movies` 用户收藏核心表
    存储海报地址、电影标题、收藏时间等用户资产数据，支持本地按评分、年份二次排序检索；
2. `movie_cache` 服务端数据镜像缓存表
    缓存首页热门、高分榜单最新 20 条电影数据；配合网络状态监听器，实现「无网络展示本地缓存，联网静默后台更新缓存」策略。

### 4.2 DataStore 轻量偏好存储
舍弃老旧同步阻塞的 SharedPreferences，采用协程友好的 DataStore 存储轻量配置：
- 搜索历史：自动持久化最近 3 条搜索关键词，序列化列表存储；
- 深色模式配置：全局主题状态持久化，App 重启自动还原用户明暗视觉偏好。

## 5. 网络层与全链路性能优化
### 5.1 网络基础栈
`Retrofit 2 + OkHttp 4 + Gson` 标准三层网络架构，统一请求拦截、异常处理、响应解析。

### 5.2 图片加载加速方案
原生 TMDB 图片源加载速度慢，引入全球边缘分布式图片代理 `images.weserv.nl`，转发所有海报、背景图请求，实测图片加载速度提升约 300%。

### 5.3 请求防抖与重复请求拦截
1. **搜索输入防抖**：通过协程 `Job.cancel()` + `delay(400)` 实现输入节流，仅用户停止输入 400ms 后发起搜索请求，减少无效网络调用；
2. **分页加载锁**：分页接口增加 `isNextPageLoading` 布尔标记，上滑加载时上锁，防止快速滑动触发重复分页请求，避免列表重复渲染相同数据。

## 6. UI/UX 交互设计亮点
1. **Edge-to-Edge 全屏沉浸式详情页**
    页面背景图延伸至系统状态栏下方，搭配透明顶部导航栏，打造巨幕电影海报视觉效果；

## 7. 核心技术难点与落地解决方案
### 难点1：分页加载数据重复 ID 列表崩溃
- 问题描述：分页接口数据后端排序动态变化，拼接新旧列表 `oldList + newList` 会出现重复 ID；Compose 列表依赖 Item Key 唯一标识，重复 Key 直接引发页面闪退；
- 解决方案：ViewModel 数据处理链路强制调用 `.distinctBy { it.id }` 根据电影 ID 全局去重，从数据流源头消除重复数据，保证列表渲染稳定。

### 难点2：沉浸式状态栏按钮与系统UI重叠冲突
- 问题描述：全屏背景穿透状态栏后，返回按钮与系统时间、电量图标重叠，操作按钮不可见；
- 解决方案：自定义详情页顶部导航栏，使用 `statusBarsPadding()` 自动适配不同机型系统栏高度，为返回按钮增加半透明圆形底色，任意海报背景下按钮清晰可交互。

# 10. 运行说明
- 最低 Android 版本：API 24（Android 7.0）
- 推荐 Android 版本：API 34（Android 14）
- 特殊权限：`INTERNET` 网络权限，用于请求 TMDB 影视API获取在线影片数据，无相机、通知等额外权限。
- 运行步骤：
  1. 克隆仓库：`git clone https://github.com/starry0616/2025003022-FinalProject.git`
  2. 打开 Android Studio，选择 `File -> Open`，选中本地 `2025003022-FinalProject` 项目文件夹
  3. 等待 Gradle 自动同步依赖、下载所需SDK资源
  4. 在 Device Manager 启动模拟器，或连接开启调试模式的安卓真机
  5. 点击顶部绿色 Run 按钮，编译并安装应用至设备
  6. 应用加载逻辑：优先请求线上TMDB接口；网络不通时自动读取Room本地缓存；无缓存则加载内置Mock电影数据，全部功能可正常演示。

# 11. 项目亮点
1. **完整三级数据加载容错机制**
    实现「线上网络数据 → Room离线缓存 → 本地Mock模拟数据」三级降级方案，完美解决境外TMDB接口国内访问受限问题，无网络环境下应用不会空白、崩溃，所有交互功能完整可用。

3. **双持久化存储落地**
    - Room数据库两张数据表（电影缓存表、收藏表），实现完整CRUD、模糊搜索、筛选排序；
    - DataStore持久化深浅色主题偏好，重启应用配置不丢失，完美适配Material3动态主题。
4. **完善多状态UI反馈**
    列表统一实现加载中骨架动画、空数据页面、网络错误重试页面，页面切换使用Compose原生过渡动画，交互体验流畅；同时适配系统深浅色模式，主题一键切换。
5. **标准化网络封装**
    Retrofit统一拦截异常、统一处理Loading/Success/Error状态，通过UiState密封类管理页面全部状态，代码复用性高，易维护。
